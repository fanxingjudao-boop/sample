# 仕様書：Offline Search（WPF + Lucene.NET）v1.0

## 1. 目的

ローカル/閉域環境のファイルをクロールして全文検索できる Windows デスクトップアプリを提供する。実行時に外部ネットワークへの接続/送信が一切発生しないことを保証する。

## 2. 用語

- **オフライン**: 外部ネットワーク（Internet）に一切接続しない。DNS 問い合わせも禁止。
- **外部通信**: TCP/UDP/ICMP 等の送受信、名前解決、OCSP/CRL、更新チェック、テレメトリ、クラッシュレポート送信を含む。
- **クロール**: ローカルファイルの走査・内容抽出・インデックス作成。
- **インデックス**: Lucene.NET のインデックスディレクトリ（ローカル保存）。
- **対象パス**: ユーザーが登録したフォルダ（ローカル or 閉域共有）。

## 3. 適用範囲

- OS: Windows 10/11
- 形態: WPF デスクトップアプリ（.NET）
- 入力: ローカルファイル、ローカル共有（UNC）
- 出力: ローカルインデックス、検索結果、ローカルログ

## 4. 対象範囲

- 検索エンジン: Lucene.NET 4.8 互換
- 対象データ: ローカル/閉域ネットワーク内のファイル
- 対象ファイル種別: Office/テキスト/PDF など（拡張子ごとのパーサーで拡張可能）

## 5. 非目標（v1.0ではやらない）

- UI の高度なカスタム（拡張プラグイン）
- 画像/音声/動画の内容解析
- クラウド連携、同期、外部 URL の検索
- 自動更新機構（禁止）

## 6. 非機能要件

- **オフライン保証**
  - アプリは外部ネットワークへの通信を行わない。
  - アプリ内の依存ライブラリはローカルに同梱し、起動後に追加ダウンロードを行わない。
  - テレメトリ/分析/更新チェック機能は無効または未搭載。
- **性能**
  - 初回クロールはバックグラウンドで実行し、UI の操作を妨げない。
  - 10 万ファイル規模での検索応答は 1 秒以内を目標。
- **信頼性**
  - インデックス破損時の復旧（再構築）手順を提供。
  - 例外は UI に安全に通知し、アプリはクラッシュしない。
- **セキュリティ**
  - 検索対象のアクセス権を尊重し、権限外のファイルは無視。

## 7. 機能要件

### 7.1 対象ファイル形式（v1.0 / MVP）

- 必須: `.txt`, `.md`, `.csv`, `.log`, `.pdf`, `.docx`, `.xlsx`, `.pptx`
- 抽出ライブラリは外部通信を行わないことを条件とする。

### 7.2 クロール（インデックス作成）

#### 7.2.1 対象パス管理

- ユーザーは複数の対象パスを登録できる。
- パス種別: ローカル（例: `C:\\docs`）、UNC（例: `\\\\server\\share`）。
- パスは正規化して保存（末尾 `\\` を統一、大小は Windows 基準）。
- デフォルト除外:
  - シンボリックリンク / ジャンクション（ループ・意図しない範囲の走査防止）。
  - 隠し属性ファイル（オプションで含められる）。

#### 7.2.2 除外ルール

- 拡張子除外（例: `.tmp`, `.bak`）。
- パス除外（部分一致、ワイルドカード `*` をサポート）。
- サイズ上限（デフォルト: 50MB、設定可能）。
- 例外時の挙動: 除外ではなく「失敗としてログに記録し継続」。

#### 7.2.3 インデックス作成方式

- 初回: 対象パス配下をフルスキャンしてインデックス作成。
- 差分更新: 次の条件で判定。
  - 更新日時（`LastWriteTimeUtc`）とサイズが一致: スキップ。
  - どちらかが不一致: 再抽出して更新。
- 削除反映: インデックス上に存在するが実ファイルがないものは削除。
- クロール処理はキャンセル可能（UI から停止）。

#### 7.2.4 文字エンコーディング

- `.txt`/`.log`/`.csv`/`.md` は以下の順で読み取り。
  1. BOM 付き UTF-8/UTF-16
  2. UTF-8（例外が出ない範囲）
  3. Windows-932（Shift_JIS）
- 読めない場合は「抽出失敗」としてログ記録し継続。

### 7.3 検索

#### 7.3.1 検索対象フィールド

- `content`: 本文（解析対象）
- `path`: 完全パス（検索対象外、フィルタ用）
- `filename`: ファイル名（検索対象）
- `ext`: 拡張子（フィルタ用）
- `modifiedUtcTicks`: 更新日時（ソート用）
- `size`: サイズ（表示用）

#### 7.3.2 クエリ仕様（v1.0）

- スペース区切り: AND（例: `foo bar` は `foo AND bar`）
- OR: `OR` キーワード（例: `foo OR bar`）
- NOT: 先頭 `-`（例: `foo -bar`）
- フレーズ: ダブルクォート（例: `"foo bar"`）
- フィルタ（v1.0 必須）:
  - `ext:txt`（拡張子）
  - `path:"C:\\docs"`（パス前方一致）
- 大文字小文字: 区別しない。
- 日本語対応:
  - `Lucene.Net.Analysis.Kuromoji` を使用。
  - v1.0 で日本語対応が不要な場合のみ `StandardAnalyzer` を許容。

#### 7.3.3 検索結果

- 表示項目:
  - ファイル名
  - フルパス
  - 更新日時（ローカル表示）
  - スニペット（ヒット周辺、最大 200 文字）
- ソート:
  - デフォルト: スコア降順
  - 切替: 更新日時降順
- 結果上限:
  - デフォルト 200 件（設定可能）
- ファイルを開く:
  - OS 関連付けで開く（`Process.Start` + `UseShellExecute=true`）

### 7.4 UI

#### 7.4.1 画面

- メイン画面
  - 検索ボックス
  - 検索ボタン/Enter で実行
  - 結果一覧（DataGrid）
  - 詳細ペイン（スニペット/抽出テキスト簡易表示）
  - ステータスバー（インデックス数、最終更新日時、クロール進捗）
- 設定画面
  - 対象パス追加/削除
  - 除外ルール編集
  - サイズ上限
  - インデックス保存先
  - ログレベル
  - 「インデックス再作成」ボタン

#### 7.4.2 UI 資材制約（オフライン厳守）

- WebView2/CEF/Chromium 系は禁止。
- 外部フォント、CDN、外部画像参照は禁止。
- ヘルプはローカル（同梱 md/pdf）に限定。

## 8. データ設計

### 8.1 データ保存仕様

#### 8.1.1 保存先（デフォルト）

- 設定: `%LOCALAPPDATA%\\OfflineSearch\\config.json`
- インデックス: `%LOCALAPPDATA%\\OfflineSearch\\index\\`
- ログ: `%LOCALAPPDATA%\\OfflineSearch\\logs\\app.log`

#### 8.1.2 config.json スキーマ（v1.0）

- `indexPath`: string
- `roots`: array of
  - `path`: string
  - `enabled`: bool
  - `excludeExtensions`: array<string>
  - `excludePathPatterns`: array<string>（`*` ワイルドカード）
- `maxFileSizeMB`: int
- `includeHidden`: bool
- `resultLimit`: int
- `logLevel`: string（Error/Warn/Info/Debug）

- **インデックス格納先**: ローカルアプリデータ配下。
- **フィールド例**
  - `path`（String, Stored, NotAnalyzed）
  - `file_name`（String, Stored, Analyzed）
  - `content`（Text, NotStored, Analyzed）
  - `last_modified`（Long, Stored）
  - `size`（Long, Stored）

## 9. オフライン無通信要件（最重要）

### 9.1 実行時禁止事項（N-OF）

- DNS 問い合わせ禁止。
- HTTP(S) 禁止。
- 任意の外部通信禁止（TCP/UDP/ICMP）。
- 更新チェック禁止。
- テレメトリ・クラッシュレポート送信禁止。
- 証明書失効確認（OCSP/CRL）などのネットワーク依存機能を呼ばない。

### 9.2 実装上の制約

- HttpClient, WebRequest, Dns, Socket 等のネットワーク API 利用禁止（アプリコード内）。
- 依存ライブラリが通信しないこと（通信機能があるライブラリは不採用）。
- 例外送信 SDK（Sentry 等）禁止。

## 10. テスト戦略

- xUnit による自動テストを必須とする。
- テストはローカルファイルを Temp ディレクトリに生成して行う（外部依存なし）。
- 目標:
  - インデックス作成が正しい。
  - 差分更新と削除反映が正しい。
  - クエリ仕様が動く。
  - “外部参照/通信の芽”をコードレベルで早期検知する。

## 11. 自動テスト項目（必須）

### 11.1 IndexingTests

- 初回クロールで検索できる。
  - Given: temp に 3 ファイル作成（内容にキーワード）。
  - When: インデックス作成。
  - Then: 検索で該当ファイルがヒットする。
- 差分更新が反映される。
  - Given: ファイル A に `foo`。
  - When: インデックス → ファイル A を `foo bar` に更新 → 差分更新。
  - Then: `bar` でヒットする。
- 削除が反映される。
  - Given: ファイル B を作成しインデックス。
  - When: ファイル B 削除 → 差分更新。
  - Then: ファイル B がヒットしない。
- 除外ルールが効く。
  - Given: `excludeExtensions=[".log"]`。
  - Then: `.log` はインデックスされない。
- サイズ上限が効く。
  - Given: 上限 1MB、2MB ファイル。
  - Then: 2MB は抽出スキップされログに記録。

### 11.2 QueryTests

- AND（スペース）が効く。
- OR が効く。
- NOT（`-`）が効く。
- フレーズ `"foo bar"` が効く。
- ext/path フィルタが効く。

### 11.3 SnippetTests

- ヒット箇所周辺のスニペットが 200 文字以内で返る。
- ヒット語が含まれる（最低 1 回）。

### 11.4 OfflineComplianceTests（超重要、CIで落とす）

- A. 静的文字列検査（簡易で強い）
  - リポジトリ全体をスキャンし、以下が含まれたらテスト失敗。
    - `http://`, `https://`
    - `WebView2`, `CefSharp`, `Chromium`
    - `HttpClient`, `WebRequest`, `Socket`, `Dns`
  - 例外: README など docs 内の参考 URL まで落とすと人間が泣くので、対象を `src/` 配下に限定。
- B. 参照アセンブリ検査（もう一段）
  - `src` のビルド成果物を反射で見て、アプリ本体が `System.Net.Http` を参照していたら失敗（依存が増えた瞬間に検知する）。
  - 本物の「通信がゼロ」を CI だけで完全証明は難しい。なので “通信しそうな芽を潰す検査” をガチガチに固める。オフライン環境での実地テストは受け入れ試験でやる。

## 12. ログ/監査

### 12.1 ログ要件

- ローカルファイルのみ。
- ローテーション: 1 ファイル最大 10MB、最大 5 世代。
- 本文全文はログに書かない（最大 N 文字まで、N=200）。
- ローカルログのみ出力。
- 送信を伴うログは一切無効。
- トラブルシュートのためにインデックス更新履歴を保存。

## 13. リポジトリ構成（固定）

- `src/InazumaOfflineSearch.App`（WPF）
- `src/InazumaOfflineSearch.Core`（クロール/抽出/検索）
- `tests/InazumaOfflineSearch.Tests`（xUnit）
- `docs/spec.md`（この仕様）
- `docs/test/AT-Offline.md`
- `scripts/`（ビルド/パッケージ）

## 14. ビルド/配布

- .NET: `net8.0-windows`（固定）。
- 配布: self-contained（単体で動くように）。
- GitHub Actions:
  - build + test
  - 成果物を Artifacts へ
  - tag で Release 作成（人間の承認は任意）

## 15. Definition of Done（完了条件）

- 全自動テスト（xUnit）が CI でグリーン。
- OfflineComplianceTests がグリーン。
- AT-OF-01/02 が手順通りに通る（オフライン実機）。
- インデックス作成/差分更新/削除反映/検索が仕様通り。

## 16. Codex 向け：実装開始プロンプト（そのまま貼れる）

- 「上記 docs/spec.md を満たすようにリポジトリ雛形を作成」
- 「Core に Indexer と Searcher の public API を定義してテストから駆動」
- 「tests で Temp フォルダにファイル生成して全項目を自動化」
- 「OfflineComplianceTests を実装し、src 配下の禁止文字列検査と System.Net.Http 参照検査を追加」
- 「WPF UI は最低限で OK（検索・結果・設定・再作成）」

## 17. 運用

- 初期セットアップで対象フォルダを指定。
- 定期インデックス更新スケジュール（アイドル時/ユーザー指定）。
- アプリ更新は手動配布前提（オンライン更新禁止）。

## 18. 依存関係

- .NET Desktop Runtime
- Lucene.NET 4.8
- ファイル種別ごとのパーサー（例: OpenXML, PDF）
