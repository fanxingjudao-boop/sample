# Offline Search（WPF + Lucene.NET）v1.0 向け テスト実施構築案

本リポジトリはサンプル用のため、以下に **WPF でテストを実施できる構築案** と **テストアイデア** をまとめます。要件にある「外部ネットワーク接続を一切行わない」ことを前提に、**ローカル/閉域環境で完結**する構成を想定しています。

## テスト実施できる構築（提案）

### 1. ソリューション構成（例）
- `OfflineSearch.App`：WPF アプリ本体（.NET）
- `OfflineSearch.Core`：検索/インデックス/パーサー等のドメインロジック
- `OfflineSearch.Tests`：ユニットテスト（Core 向け）
- `OfflineSearch.AppTests`：WPF/統合テスト（UI・動作確認）

### 2. テストフレームワーク
- **ユニットテスト**：xUnit / NUnit / MSTest のいずれか  
  - STA スレッドが必要な WPF テスト向けに、`ApartmentState.STA` 指定または `WpfFact` 系の属性を利用。
- **UI/統合テスト**：WPF 用の UI テストフレームワーク
  - `FlaUI`（推奨）：Windows の UI Automation を使う。
  - 可能であれば、**ローカル専用**のテスト環境で実施。

### 3. テスト実行環境
- **外部通信を完全遮断**するため、以下のいずれかを採用：
  - Windows Firewall で「既定でブロック」する専用テスト用プロファイル
  - オフライン VM / 閉域環境上での実行
- **DNS/更新チェックの禁止**を検証するため、実行時に外部ネットワークを遮断した状態でテストを行う。

### 4. CI/CD（任意）
オフライン要件が最重要のため、CI は必須ではありませんが、可能であれば以下のような構成が望ましい：
- オフラインのビルド/テスト環境
- 依存パッケージは事前に取得し、**ローカル NuGet フィード**から復元

## テストアイデア

### A. 機能テスト（Core）
- **インデックス作成テスト**  
  - 指定フォルダ内のファイルを正しく取り込み、Lucene インデックスが生成されるか。
- **検索精度テスト**  
  - 既知のテキストを含むファイルから期待される検索結果が返るか。
- **拡張子別パーサーテスト**  
  - `.txt`, `.pdf`, `.docx` 等の解析結果が期待どおりに抽出されるか。
- **更新/削除時のインデックス同期**  
  - ファイル更新/削除後に再クロールした結果が正しく反映されるか。

### B. WPF/統合テスト
- **検索 UI テスト**  
  - 検索キーワード入力 → 検索ボタン押下 → 結果が表示される一連の動作。
- **クロール設定 UI テスト**  
  - 対象フォルダの追加/削除、再クロールの実行が正しく動作するか。

### C. オフライン要件検証
- **外部通信の遮断テスト**  
  - 外部ネットワークアクセスを強制的に遮断した状態で動作するか。
- **DNS 問い合わせの禁止テスト**  
  - 実行中に DNS クエリが発生しないことを検証（ネットワーク監視ツールで確認）。

## 仕様に基づくテスト条件（v1.0）

### 6. 非機能要件に対するテスト条件
- **オフライン保証**
  - アプリ実行中に TCP/UDP/ICMP 等の外部通信、DNS 問い合わせ、OCSP/CRL、更新チェックが発生しない。
  - 依存ライブラリはローカル同梱済みで、起動後に追加ダウンロードが発生しない。
  - テレメトリ/分析/クラッシュレポート送信は無効または未搭載。
- **性能**
  - 初回クロールはバックグラウンドで実行し、UI 操作を妨げない。
  - 10 万ファイル規模での検索応答が 1 秒以内を目標（性能試験で測定）。
- **信頼性**
  - インデックス破損時に再構築手順を提供できる。
  - 例外は UI に安全に通知され、アプリがクラッシュしない。
- **セキュリティ**
  - 検索対象のアクセス権を尊重し、権限外のファイルは無視される。

### 7. 機能要件に対するテスト条件

#### 7.1 対象ファイル形式（v1.0 / MVP）
- 必須: `.txt`, `.md`, `.csv`, `.log`, `.pdf`, `.docx`, `.xlsx`, `.pptx`
- 抽出ライブラリは外部通信を行わないことを条件とする。

#### 7.2 クロール（インデックス作成）
##### 7.2.1 対象パス管理
- 複数の対象パスを登録できる（ローカル/UNC）。
- パスは正規化して保存（末尾 `\\` 統一、大小は Windows 基準）。
- デフォルト除外: シンボリックリンク/ジャンクション、隠し属性ファイル（オプションで含める）。

##### 7.2.2 除外ルール
- 拡張子除外（例: `.tmp`, `.bak`）。
- パス除外（部分一致、ワイルドカード `*`）。
- サイズ上限（デフォルト 50MB、設定可能）。
- 例外時は「失敗としてログに記録し継続」する。

##### 7.2.3 インデックス作成方式
- 初回はフルスキャン。
- 差分更新は `LastWriteTimeUtc` とサイズの一致/不一致で判定。
- 削除反映: インデックスにあるが実ファイルがないものを削除。
- クロール処理は UI からキャンセル可能。

##### 7.2.4 文字エンコーディング
- `.txt`/`.log`/`.csv`/`.md` は以下の順で読み取り:
  1. BOM 付き UTF-8/UTF-16
  2. UTF-8
  3. Windows-932（Shift_JIS）
- 読めない場合は「抽出失敗」としてログ記録し継続。

#### 7.3 検索
##### 7.3.1 検索対象フィールド
- `content`: 本文（解析対象）
- `path`: 完全パス（検索対象外、フィルタ用）
- `filename`: ファイル名（検索対象）
- `ext`: 拡張子（フィルタ用）
- `modifiedUtcTicks`: 更新日時（ソート用）
- `size`: サイズ（表示用）

##### 7.3.2 クエリ仕様（v1.0）
- スペース区切り: AND（例: `foo bar`）
- OR: `OR` キーワード
- NOT: 先頭 `-`
- フレーズ: ダブルクォート
- フィルタ（v1.0 必須）:
  - `ext:txt`
  - `path:"C:\\docs"`（パス前方一致）
- 大文字小文字: 区別しない。
- 日本語対応:
  - `Lucene.Net.Analysis.Kuromoji` を使用。
  - v1.0 で日本語対応不要なら `StandardAnalyzer` を許容。

##### 7.3.3 検索結果
- 表示項目: ファイル名、フルパス、更新日時（ローカル表示）、スニペット（最大 200 文字）。
- ソート: デフォルトはスコア降順、切替で更新日時降順。
- 結果上限: デフォルト 200 件（設定可能）。
- ファイルを開く: `Process.Start` + `UseShellExecute=true`。

#### 7.4 UI
##### 7.4.1 画面
- メイン画面: 検索ボックス、検索実行、結果一覧（DataGrid）、詳細ペイン、ステータスバー。
- 設定画面: 対象パス追加/削除、除外ルール編集、サイズ上限、インデックス保存先、ログレベル、インデックス再作成。

##### 7.4.2 UI 資材制約（オフライン厳守）
- WebView2/CEF/Chromium 系は禁止。
- 外部フォント、CDN、外部画像参照は禁止。
- ヘルプはローカル（同梱 md/pdf）のみ。

### WPF に連動するテスト（例）
- **メイン画面の検索フロー**: 検索ボックス入力 → 検索実行 → 結果一覧/詳細ペイン/ステータスバーが更新される。
- **設定画面の変更反映**: 対象パス/除外ルール/サイズ上限を更新し、再クロールで結果が反映される。
- **UI 資材制約の検証**: WebView 系コントロールが使われていないこと、外部リソース参照がないことを確認する。

## 8. データ設計

### 8.1 データ保存仕様

#### 8.1.1 保存先（デフォルト）
- 設定: `%LOCALAPPDATA%\\OfflineSearch\\config.json`
- インデックス: `%LOCALAPPDATA%\\OfflineSearch\\index\\`
- ログ: `%LOCALAPPDATA%\\OfflineSearch\\logs\\app.log`

#### 8.1.2 config.json スキーマ（v1.0）
- `indexPath`: string
- `roots`: array of
  - `path`: string
  - `enabled`: bool
  - `excludeExtensions`: array<string>
  - `excludePathPatterns`: array<string>（`*` ワイルドカード）
- `maxFileSizeMB`: int
- `includeHidden`: bool
- `resultLimit`: int
- `logLevel`: string（Error/Warn/Info/Debug）

- **インデックス格納先**: ローカルアプリデータ配下。
- **フィールド例**
  - `path`（String, Stored, NotAnalyzed）
  - `file_name`（String, Stored, Analyzed）
  - `content`（Text, NotStored, Analyzed）
  - `last_modified`（Long, Stored）
  - `size`（Long, Stored）

## 9. オフライン無通信要件（最重要）

### 9.1 実行時禁止事項（N-OF）
- DNS 問い合わせ禁止。
- HTTP(S) 禁止。
- 任意の外部通信禁止（TCP/UDP/ICMP）。
- 更新チェック禁止。
- テレメトリ・クラッシュレポート送信禁止。
- 証明書失効確認（OCSP/CRL）などのネットワーク依存機能を呼ばない。

### 9.2 実装上の制約
- HttpClient, WebRequest, Dns, Socket 等のネットワーク API 利用禁止（アプリコード内）。
- 依存ライブラリが通信しないこと（通信機能があるライブラリは不採用）。
- 例外送信 SDK（Sentry 等）禁止。

## 10. テスト戦略
- xUnit による自動テストを必須とする。
- テストはローカルファイルを Temp ディレクトリに生成して行う（外部依存なし）。
- 目標:
  - インデックス作成が正しい。
  - 差分更新と削除反映が正しい。
  - クエリ仕様が動く。
  - “外部参照/通信の芽”をコードレベルで早期検知する。

## 11. 自動テスト項目（必須）

### 11.1 IndexingTests
- 初回クロールで検索できる。
  - Given: temp に 3 ファイル作成（内容にキーワード）。
  - When: インデックス作成。
  - Then: 検索で該当ファイルがヒットする。
- 差分更新が反映される。
  - Given: ファイル A に `foo`。
  - When: インデックス → ファイル A を `foo bar` に更新 → 差分更新。
  - Then: `bar` でヒットする。
- 削除が反映される。
  - Given: ファイル B を作成しインデックス。
  - When: ファイル B 削除 → 差分更新。
  - Then: ファイル B がヒットしない。
- 除外ルールが効く。
  - Given: `excludeExtensions=[".log"]`。
  - Then: `.log` はインデックスされない。
- サイズ上限が効く。
  - Given: 上限 1MB、2MB ファイル。
  - Then: 2MB は抽出スキップされログに記録。

### 11.2 QueryTests
- AND（スペース）が効く。
- OR が効く。
- NOT（`-`）が効く。
- フレーズ `"foo bar"` が効く。
- ext/path フィルタが効く。

### 11.3 SnippetTests
- ヒット箇所周辺のスニペットが 200 文字以内で返る。
- ヒット語が含まれる（最低 1 回）。

### 11.4 OfflineComplianceTests（超重要、CIで落とす）
- A. 静的文字列検査（簡易で強い）
  - リポジトリ全体をスキャンし、以下が含まれたらテスト失敗。
    - `http://`, `https://`
    - `WebView2`, `CefSharp`, `Chromium`
    - `HttpClient`, `WebRequest`, `Socket`, `Dns`
  - 例外: README など docs 内の参考 URL まで落とすと人間が泣くので、対象を `src/` 配下に限定。
- B. 参照アセンブリ検査（もう一段）
  - `src` のビルド成果物を反射で見て、アプリ本体が `System.Net.Http` を参照していたら失敗（依存が増えた瞬間に検知する）。
  - 本物の「通信がゼロ」を CI だけで完全証明は難しい。なので “通信しそうな芽を潰す検査” をガチガチに固める。オフライン環境での実地テストは受け入れ試験でやる。

## 12. ログ/監査

### 12.1 ログ要件
- ローカルファイルのみ。
- ローテーション: 1 ファイル最大 10MB、最大 5 世代。
- 本文全文はログに書かない（最大 N 文字まで、N=200）。
- ローカルログのみ出力。
- 送信を伴うログは一切無効。
- トラブルシュートのためにインデックス更新履歴を保存。

## 14. ビルド/配布
- .NET: `net8.0-windows`（固定）。
- 配布: self-contained（単体で動くように）。
- GitHub Actions:
  - build + test
  - 成果物を Artifacts へ
  - tag で Release 作成（人間の承認は任意）

## 15. Definition of Done（完了条件）
- 全自動テスト（xUnit）が CI でグリーン。
- OfflineComplianceTests がグリーン。
- AT-OF-01/02 が手順通りに通る（オフライン実機）。
- インデックス作成/差分更新/削除反映/検索が仕様通り。

## 16. Codex 向け：実装開始プロンプト（そのまま貼れる）
- 「上記 docs/spec.md を満たすようにリポジトリ雛形を作成」

- 「tests で Temp フォルダにファイル生成して全項目を自動化」

## 17. 運用

- アプリ更新は手動配布前提（オンライン更新禁止）。
